Jaza uses webhooks to notify your backend about payment and credit events. When a customer tops up their wallet, the payment gateway notifies Jaza, Jaza credits the wallet and appends a ledger entry, then Jaza sends an event to your configured endpoint so your system can react immediately.

## How webhooks work

1. A customer completes a top-up through the TopUpModal.
2. The Mobile Money or card gateway confirms the payment and fires a webhook to Jaza.
3. Jaza validates the payment, increases the customer's wallet balance, and records a `TOPUP` ledger entry.
4. Jaza sends a webhook event to your endpoint with the details.
5. Your server receives the event and updates your own records or triggers downstream logic.

## Event types

| Event | Description |
| --- | --- |
| `topup.completed` | A top-up payment succeeded and credits were added |
| `topup.failed` | A top-up payment failed and no credits were added |

## Example payload

Here is what a `topup.completed` event looks like:

```json
{
  "event": "topup.completed",
  "data": {
    "customer_id": "cus_abc123def",
    "amount_credits": 500,
    "payment_method": "m-pesa",
    "created_at": "2026-08-15T09:23:17Z"
  }
}
```

The `topup.failed` payload uses the same shape but sets `event` to `topup.failed` and may include a `failure_reason` field.

## Verifying webhook signatures

Jaza signs every webhook request with HMAC-SHA256 using your webhook secret. Verify the signature before processing the payload to ensure the event came from Jaza.

<CodeGroup>

```javascript Node.js
const crypto = require('crypto');

function verifySignature(payload, signature, secret) {
  const expected = crypto
    .createHmac('sha256', secret)
    .update(payload, 'utf8')
    .digest('hex');
  return crypto.timingSafeEqual(
    Buffer.from(signature, 'hex'),
    Buffer.from(expected, 'hex')
  );
}

// Usage
const payload = JSON.stringify(req.body);
const signature = req.headers['x-jaza-signature'];
if (!verifySignature(payload, signature, process.env.JAZA_WEBHOOK_SECRET)) {
  return res.status(401).send('Invalid signature');
}
```

</CodeGroup>

## Retry behavior

If your endpoint returns a non-2xx status or does not respond within the timeout window, Jaza retries delivery automatically:

- **Max retries**: 3 attempts
- **Backoff strategy**: Exponential backoff with jitter between attempts
- **Ordering**: Jaza does not guarantee strict ordering across retries. Design your handler to be idempotent or deduplicate using the event payload fields.

<Note>
  Jaza retries are intended for transient failures. If your endpoint is down for an extended period, events may be dropped after the final retry. Monitor your webhook logs in the Jaza dashboard.
</Note>
