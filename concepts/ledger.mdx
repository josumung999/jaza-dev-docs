The Jaza ledger is an append-only log of every credit event that occurs in your app. Rather than storing a balance number that gets overwritten, Jaza derives each wallet's balance from the sum of its ledger entries. This design guarantees that your audit trail is complete, tamper-evident, and easy to reconcile.

## What the ledger records

Every time credits move, Jaza appends a new ledger entry. The entry captures the event type, amount, customer, and context so you can trace any balance back to its source.

### Entry types

| Type | Description |
| --- | --- |
| `TOPUP` | Credits added from a payment |
| `CONSUME` | Credits deducted by a feature call |
| `REFUND` | Credits returned to a customer (planned) |

### Entry fields

Each ledger entry contains the following fields:

- `id`: Unique identifier for the entry
- `type`: Event type (`TOPUP`, `CONSUME`, or `REFUND`)
- `amount`: Number of credits moved (positive integer)
- `feature`: Feature key, present only for `CONSUME` entries
- `customer_id`: The wallet owner (`cus_` ID)
- `created_at`: ISO 8601 timestamp of the event
- `idempotency_key`: The key you passed to prevent duplicate processing

## Why immutability matters

Because the ledger is append-only, balances are never edited in place. To find a customer's current balance, Jaza sums every entry for that `customer_id`. This means:

- **No balance drift**: There is no stored balance field that can silently diverge from the transaction history.
- **Trivial auditing**: Any discrepancy can be resolved by summing the ledger entries for a customer.
- **Full traceability**: Every top-up and every feature consumption is preserved with its original idempotency key.

## Example ledger entry

Here is what a single `CONSUME` entry looks like in the ledger:

```json
{
  "id": "led_abc123def456",
  "type": "CONSUME",
  "amount": 10,
  "feature": "AI_PROMPT",
  "customer_id": "cus_abc123def",
  "created_at": "2026-08-15T09:23:17Z",
  "idempotency_key": "idempotency_20260815_001"
}
```

A `TOPUP` entry has the same shape but omits the `feature` field and uses `type: "TOPUP"`.
