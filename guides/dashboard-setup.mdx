Pricing and markets live in the [dashboard](https://jaza.dev/dashboard), not in a separate rate-card API. Configure once, then enforce costs with `jaza.consume({ featureCode })` and sell packs through the client top-up UI.

## 1. Create an app

1. Open the [dashboard](https://jaza.dev/dashboard).
2. Create an app and pick a clear name.
3. Stay in **sandbox** until the flow works end to end.

## 2. Enable countries

Under **App Settings → Countries**, enable the Mobile Money markets you need. Jaza routes deposits through its partners — you do **not** open a PawaPay account or manage multi-currency settlement yourself.

## 3. Define features

Under **Features**, add each billable action:

| Field | Example |
| --- | --- |
| Feature code | `SEND_MESSAGE` |
| Credits cost | `5` |

Your backend will pass the same `featureCode` to `jaza.consume()`. Costs also appear in the client session snapshot for `JazaActionButton`.

## 4. Define bundles

Under **Bundles**, add credit packs shown in the client top-up UI (label, price, credits granted).

## 5. Copy API keys

| Key | Env var (typical) | Prefix |
| --- | --- | --- |
| Secret | `JAZA_SECRET_KEY` | `jz_test_sk_…` / `jz_live_sk_…` |
| Publishable | Client env (`EXPO_PUBLIC_…` / `NEXT_PUBLIC_…`) + server `JAZA_PUBLIC_KEY` | `jz_test_pk_…` / `jz_live_pk_…` |

<Warning>
  Never ship the secret key in a mobile binary or public repo.
</Warning>

## 6. Webhooks (optional)

Under **App Settings → Webhooks**, add HTTPS endpoints, pick top-up and consumption events, and copy the signing secret. Verify with `jaza.webhooks.constructEvent`. See [Webhooks](/guides/webhooks).

For in-app UX after a top-up, use `onTopUpComplete` and the SDK wallet refresh — you do not need webhooks for the sheet to update balance.
