---
title: "POST /credits/consume — Deduct Credits from a Wallet"
sidebarTitle: "Consume"
description: "Deduct credits for a billable feature. Idempotent and race-safe — the same Idempotency-Key always returns the same result without double-charging."
---

Call this endpoint from your backend when a user performs a billable action. `consume` is idempotent and race-safe, so you can safely retry on network errors without double-charging the customer.

## Endpoint

```text
POST /credits/consume
```

## Headers

| Header | Value | Required |
| --- | --- | --- |
| `Authorization` | `Bearer <YOUR_SECRET_KEY>` | Yes |
| `Content-Type` | `application/json` | Yes |
| `Idempotency-Key` | A unique key for this operation | Strongly recommended |

## Request body

<ParamField body="feature" type="string" required>
  The feature key as defined in your rate card. Must exist and be active.
</ParamField>

<ParamField body="userId" type="string" required>
  The Jaza customer ID (`cus_...`) whose wallet will be debited.
</ParamField>

<ParamField body="idempotencyKey" type="string" optional>
  An alternative to the `Idempotency-Key` header. If both are provided, the header wins.
</ParamField>

## Response fields

<ResponseField name="success" type="boolean">
  `true` when the deduction succeeded.
</ResponseField>

<ResponseField name="creditsUsed" type="integer">
  Number of credits deducted.
</ResponseField>

<ResponseField name="balanceAfter" type="integer">
  Customer's wallet balance after the deduction.
</ResponseField>

<ResponseField name="ledgerEntryId" type="string">
  ID of the immutable ledger entry for this transaction.
</ResponseField>

## Error responses

If the customer's balance is lower than the feature cost, Jaza returns HTTP `402`:

```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Customer balance is too low for this feature.",
    "requestId": "req_7f8a9b2c3d4e"
  }
}
```

## Examples

<CodeGroup>

```bash curl
curl -X POST https://api.jaza.dev/v1/credits/consume \
  -H "Authorization: Bearer jz_test_sk_4eC39HqLyjWDarjtT1zdp7dc" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: consume-2026-08-01-001" \
  -d '{
    "feature": "SEND_SMS",
    "userId": "cus_9xY7zW2vQpLk"
  }'
```

```js Node
import { Jaza } from "@jazadev/node";

const jaza = new Jaza({ secretKey: process.env.JAZA_SECRET_KEY });

const result = await jaza.consume({
  feature: "SEND_SMS",
  userId: "cus_9xY7zW2vQpLk",
  idempotencyKey: "consume-2026-08-01-001",
});

console.log(result.balanceAfter);
```

</CodeGroup>

### Full error-handling example (Node.js)

```js
import { Jaza } from "@jazadev/node";

const jaza = new Jaza({ secretKey: process.env.JAZA_SECRET_KEY });

async function billUser(feature, userId) {
  const idempotencyKey = `${userId}-${feature}-${Date.now()}`;

  try {
    const result = await jaza.consume({
      feature,
      userId,
      idempotencyKey,
    });
    return { ok: true, balanceAfter: result.balanceAfter };
  } catch (err) {
    if (err.code === "INSUFFICIENT_BALANCE") {
      return { ok: false, reason: "insufficient_balance" };
    }
    // Network or server error — safe to retry because of idempotency key
    throw err;
  }
}
```

<Warning>
  Always pass an `Idempotency-Key` header (or `idempotencyKey` in the body). Without it, a network retry can deduct credits twice.
</Warning>
